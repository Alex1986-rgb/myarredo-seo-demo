# Как склонировать и оптимизировать сайт локально на MacBook (с уникальным контентом на каждой странице)

Цель: получить у каждой страницы **уникальный** SEO-текст, уникальные 8 FAQ и уникальное
описание товара — как в SeoMarket. Уникальность в масштабе 68k страниц даёт **LLM,
который пишет текст под каждую страницу** из её полей (у SeoMarket это делает бэкенд
через Lovable AI/Gemini). Локально на Mac это тот же принцип.

## 1. Что нужно на MacBook
- **Node.js** (уже установлен: `node -v` → v26). Если нет: `brew install node`.
- **Этот репозиторий** (тулкит + шаблоны): `git clone https://github.com/Alex1986-rgb/myarredo-seo-demo`.
- **LLM для генерации уникального текста** — один из вариантов:
  - **(A) Облачный API-ключ** (лучшее качество, платно): OpenAI, Anthropic или Google Gemini.
    Задаётся переменной окружения, пайплайн вызывает его на каждую страницу.
  - **(B) Локальная модель через Ollama** (бесплатно, офлайн): `brew install ollama`,
    затем `ollama pull qwen2.5:7b` (для 8 ГБ RAM берите модель поменьше, напр. `qwen2.5:3b`).
    Пайплайн обращается к `http://localhost:11434`.

> На вашем Mac 8 ГБ RAM — локальные модели тянут только небольшие (3–7B, квантованные),
> качество ниже. Для продакшн-текстов практичнее облачный ключ или прогон партиями.

## 2. Порядок работы
```bash
# 1) клонировать тулкит
git clone https://github.com/Alex1986-rgb/myarredo-seo-demo && cd myarredo-seo-demo

# 2) собрать список всех URL из карты сайта (68 831)
node toolkit/fetch-sitemap.mjs        # → urls.txt   (или используйте docs/urls.txt)

# 3) (опц.) аудит: статусы, alt, canonical, title/desc, Schema по всему сайту
node toolkit/crawl.mjs && node toolkit/aggregate.mjs

# 4) задать LLM:
export SEO_LLM=openai   OPENAI_API_KEY=sk-...        # или
export SEO_LLM=anthropic ANTHROPIC_API_KEY=sk-ant-... # или
export SEO_LLM=gemini    GEMINI_API_KEY=...           # или
export SEO_LLM=ollama    OLLAMA_MODEL=qwen2.5:7b      # локально (ollama serve запущен)

# 5) сгенерировать уникально-оптимизированные страницы (партиями по N)
node toolkit/optimize-llm.mjs urls.txt   # → site/*.html + assets

# 6) залить папку site/ на хостинг (или отдать заказчику)
```

## 3. Что делает `optimize-llm.mjs` на каждой странице
1. Скачивает страницу (с браузерными заголовками — обход антибота nginx, см. `headers.mjs`).
2. Извлекает поля (название, тип, фабрика, коллекция, артикул, материал, размеры).
3. Просит LLM написать **уникальные** под этот товар: верхнее описание, SEO-текст и 8 FAQ
   (строго из полей, без выдумок).
4. Вставляет мета (title ≤60, description ≤160), canonical, alt, JSON-LD
   (Product/Offer/BreadcrumbList/FAQPage), верхнее описание и нижний SEO-блок.
5. Сохраняет в `site/`.

## 4. Масштаб и стоимость
- 68 831 страница × ~1 вызов LLM. На облачном API — считайте по токенам (примерно
  1–2k токенов на страницу). Гоняйте партиями, с кэшем (не переписывать уже готовые).
- Полный статический экспорт 68k — тяжёлый (десятки ГБ), для продакшена лучше внедрить
  генерацию **в CMS-шаблоны** (фрагменты в `templates/`), чтобы SEO-текст создавался
  на лету/при сохранении товара — тогда «сайт» остаётся динамическим, а SEO-контент
  уникален на всех страницах.

Демо в `demo/` показывает результат на образцах всех типов страниц; категории и часть
карточек написаны уникально (каждая — отдельным проходом), что и подтверждает подход.
